# Sending Data to KloudMate

Choose the ingestion path that matches your environment and how much control you want over telemetry collection.

## Recommended Starting Points

- Use **KM Agent** if you want the fastest path for infrastructure, logs, traces, and zero-code visibility.
- Use **OpenTelemetry Collector** if you already run OTel and want to keep your existing telemetry pipelines.
- Use **AWS**or**Azure** integrations if you want to onboard cloud telemetry without instrumenting every workload directly.
- Use **Prometheus integration** when your metrics already exist in Prometheus and you want to forward them into KloudMate.

## Common Rollout Pattern

1. Start with [KM Agent](../km-agent/index.mdx) for baseline telemetry and infrastructure visibility.
2. Add [OpenTelemetry](../opentelemetry/index.mdx) where you need richer application tracing or custom instrumentation.
3. Layer in cloud-specific integrations for AWS, Azure, or Prometheus where those data sources already exist.
