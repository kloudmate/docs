KloudMate doesn't ship its own profiling agent — it speaks the [Pyroscope](https://grafana.com/oss/pyroscope/) ingest protocol at `https://otel.kloudmate.com/v1/profiles/pyroscope`, authenticated with Basic auth (`KloudMate` as the username, your Ingest API key as the password). Any Pyroscope-compatible SDK works out of the box; pick your language below for the exact install and config steps.

## Which profile types you get

Every SDK reports CPU (wall or on-CPU time, depending on the runtime); several also report memory. The exact set shows up in [Profile Types](/profiling/profile-types/) once your service has sent its first batch:

| Language | CPU | Memory |
|---|---|---|
| Go | ✅ | ✅ (heap) |
| Java | ✅ | ✅ (alloc, via async-profiler) |
| Python | ✅ | ✅ (if built with tracemalloc support) |
| Node.js | ✅ | ✅ (heap) |
| Ruby | ✅ | — |
| .NET | ✅ | ✅ (alloc) |
| Rust | ✅ | — |

## Not on this list?

If your language isn't here, check whether it has its own community Pyroscope SDK, or run the [eBPF profiler](./ebpf/) instead — it samples any process on the host without touching application code, at the cost of function-level (not line-level) detail.
