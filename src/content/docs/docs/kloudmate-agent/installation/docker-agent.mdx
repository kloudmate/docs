This document guides you through installing the **KloudMate Agent** on your host using Docker for **host metrics** and **log collection**.

## **What the Docker Agent Monitors**

Once installed, the Docker Agent collects:

- **Container metrics:** CPU, memory, network, and disk usage for each running container
- **Container lifecycle events:** start, stop, restart
- **Host metrics:** CPU, memory, disk, and network usage of the Docker host
- **Container and host logs:** stdout/stderr from containers and system logs from host
- **Alerts:** Configure thresholds for containers or the host to notify on performance issues
- **Dashboards:** Pre-built views for container-level and host-level performance

This allows you to monitor **containers and host together**, troubleshoot performance issues, and correlate logs with metrics.

## **Log Integration**

By default, the KloudMate Agent collects host and container logs.

To collect application log **files** on the Docker host, use log monitoring: from the agent's **Logs** tab you point the agent at a folder and file-name pattern and choose how to parse each line (plain text, JSON, or a regular expression). Multiline grouping, for stack traces or pretty-printed JSON, is a modifier you apply on top of any format, and you can preview the parsed records before you save. See [Log monitoring](../../log-monitoring/).

For a hand-written `filelog` receiver in manual mode, see [Collect File Logs with KloudMate Agent](../../../logs/collect-file-logs/).

## Coverage and configuration

In Docker mode the agent collects host and container metrics, container and host logs, and, where the host kernel supports it, the [eBPF baseline](../../ebpf-observability/) (RED metrics, service map, and Database Activity Monitoring) across your containers with no code changes. Per-container application injection is being rolled out; see [Docker platform notes](../../platform-notes/docker/) for current coverage.

New agents start in managed mode, so KloudMate generates the collector configuration for you. See the [configuration model](../../concepts/config-model/).
