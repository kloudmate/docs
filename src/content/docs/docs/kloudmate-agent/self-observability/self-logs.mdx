Self-logs bring the agent's own error output into KloudMate, so you can diagnose a failing agent without opening a shell on the host. Like the [health metrics](../health-metrics/), they are shipped out-of-band, on a path independent of the collector, so an error survives even when the collector cannot run. Self-logs apply on all deployment modes.

## What it ships

The agent forwards its own **ERROR-level logs** directly to KloudMate. It ships only errors, not routine debug or info messages, so the volume stays low and the signal stays high. Each log record carries attributes that tell you where the error came from:

- The **source** within the agent, such as the check-in, discovery, instrumentation, or the collector.
- The **host or node** the agent runs on.
- The **agent version**.

## On Kubernetes

On Kubernetes, self-logs are shipped per node, carried with per-node identity, so you can see errors from each node's collector and from the fleet manager without running `kubectl logs`. See [Kubernetes platform notes](../../platform-notes/kubernetes/).

## Enabling it

Self-logs are on by default, controlled by the `KM_AGENT_ERROR_LOGS` setting. Leaving them on means agent errors are always visible in KloudMate.
