eBPF (Extended Berkeley Packet Filter) is a modern technology that allows the KloudMate Agent to observe your applications directly from the Linux operating system kernel. This means you get deep visibility into network traffic, database queries, and application performance **without having to change a single line of your code or install any SDKs**.

If you are running on a Linux environment, enabling eBPF is the preferred "zero-code" path to start monitoring your services instantly.

## What eBPF Gives You

When eBPF is enabled through the KloudMate Agent, KloudMate can automatically collect:

- **Application Performance Metrics**: RED metrics (Request rate, Error rate, and Duration/latency).
- **Traces**: Automatically generated trace spans for your network traffic flows.
- **Service Dependencies**: Information used to build visual Service Maps in the APM dashboard.
- **Network Telemetry**: Low-level L3 and L4 network flow metrics.
- **Database Activity**: Kernel-level database query signals used by [Database Activity Monitoring](../../database-monitoring/database-activity-monitoring-dam/).

## Where This Data Appears

After eBPF data is flowing, use:

- [APM](../../apm-and-tracing/apm-views/) for service-level latency, throughput, and dependency views
- [Traces](../../apm-and-tracing/) for request-level trace inspection
- [Database Activity Monitoring](../../database-monitoring/database-activity-monitoring-dam/) for kernel-level database visibility

## Prerequisites

- A Linux host or Kubernetes node
- Kernel `5.8+` is highly recommended, though some features are available on `4.18+`
- Sufficient privileges for the KloudMate Agent to run eBPF programs
- The KloudMate Agent installed on the host or cluster

Use these setup guides first:

- [Linux](../installation/linux-agent/)
- [Kubernetes](../installation/kubernetes-agent/)
- [Configuration & Management](../management/)

## Recommended Rollout

1. Install the KloudMate Agent on your Linux server or Kubernetes cluster.
2. Enable APM or eBPF-related features in the agent configuration via the web UI.
3. Start with this broad zero-code coverage to get immediate visibility.
4. Add [Manual Instrumentation](../../apm-and-tracing/manual-instrumentation/) only where you need custom business logic spans or richer application context.

## Base eBPF Configuration

The eBPF receiver is configured through the KloudMate Agent `config.yaml` using the web editor.

```yaml
metrics:
  features:
    - application
    - application_span
    - network

discovery:
  services:
    - name: all-services
      namespace: default
      open_ports: "80, 443, 8080, 8443, 5432, 3306, 6379, 9092, 27017"

network:
  enable: true
  source: tc
  direction: both

attributes:
  kubernetes:
    enable: true
```

This configuration enables:

- Service-level RED metrics
- Span generation for supported traffic
- Network telemetry
- Kubernetes enrichment when applicable

## Advanced eBPF Options

Use the `ebpf` block for database heuristics and cache tuning:

```yaml
ebpf:
  heuristic_sql_detect: true
  mysql_prepared_statements_cache_size: 1024
  postgres_prepared_statements_cache_size: 1024
```

This is especially relevant for high-load database environments and for [Database Activity Monitoring](../../database-monitoring/database-activity-monitoring-dam/).

## Kubernetes Notes
