Use this guide to collect host metrics from Linux or Windows systems with the KM Agent. The KM Agent uses the OpenTelemetry `hostmetrics` receiver to collect CPU, memory, disk, filesystem, paging, network, and optional process-level metrics.

## Prerequisites

- Install the [KM Agent](../../km-agent/) on the server you want to monitor.
- Obtain your KloudMate API key.
- Identify whether the host runs on-premises, AWS EC2, or Azure so you can use the correct resource-detection processor.

## Step 1: Configure the Host Metrics Receiver

Add or update the `hostmetrics` receiver in the agent configuration:

```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization:
            enabled: true
      load:
        cpu_average: true
      memory:
        metrics:
          system.memory.utilization:
            enabled: true
      filesystem:
        metrics:
          system.filesystem.usage:
            enabled: true
          system.filesystem.utilization:
            enabled: true
      disk: {}
      network: {}
      # Enable on Linux if you need process counts by state.
      # processes: {}
      # Enable if you need per-process resource metrics.
      # process:
      #   metrics:
      #     process.cpu.utilization:
      #       enabled: true
      #     process.memory.utilization:
      #       enabled: true
```

<hint type="info">
  `processes: {}` is useful on Linux systems. It is not typically used on Windows hosts.
</hint>

## Step 2: Add Resource Detection

Choose the processor configuration that matches your environment.

### Generic Host

```yaml
processors:
  batch:
    send_batch_size: 10000
    timeout: 30s
  resourcedetection:
    detectors: [system]
    system:
      resource_attributes:
        host.name:
          enabled: true
        host.id:
          enabled: true
        os.type:
          enabled: false
  resource:
    attributes:
      - key: service.name
        action: insert
        from_attribute: host.name
```

### AWS EC2

```yaml
processors:
  batch:
    send_batch_size: 10000
    timeout: 30s

  resourcedetection/ec2:
    detectors: ["ec2"]
    ec2:
      tags:
        - ^tag1$
        - ^tag2$
        - ^label.*$
        - ^Name$

  resource:
    attributes:
      - key: service.name
        action: insert
        from_attribute: ec2.tag.Name
      - key: service.instance.id
        action: insert
        from_attribute: host.id
```

<hint type="info">
  If you want EC2 tags on telemetry, attach an IAM role that allows `ec2:DescribeTags`.
</hint>

### Azure Virtual Machines

```yaml
processors:
  batch:
    send_batch_size: 10000
    timeout: 30s

  resourcedetection/azure:
    detectors: ["azure"]
    azure:
      tags:
        - ^tag1$
        - ^tag2$
        - ^label.*$
        - ^Name$

  resource:
    attributes:
      - key: service.name
        action: insert
        from_attribute: azure.vm.name
      - key: service.instance.id
        action: insert
        from_attribute: host.id
```

## Step 3: Export Metrics to KloudMate

```yaml
exporters:
  debug:
    verbosity: detailed
  otlphttp:
    endpoint: "https://otel.kloudmate.com:4318"
    headers:
      Authorization: xxxxxxxx

service:
  pipelines:
    metrics:
      receivers: [hostmetrics]
      processors: [batch, resourcedetection, resource]
      exporters: [debug, otlphttp]
```

If you use the EC2 or Azure variants above, update the processor names in the `metrics` pipeline accordingly.

## Step 4: Restart the Agent

For Linux:

```bash
systemctl restart kmagent
systemctl status kmagent
```

For Windows:

1. Open `services.msc`.
2. Find the `KloudMate Agent` service.
3. Restart the service.

## Step 5: Validate in KloudMate

After the agent restarts:

- open [Explore](../explore/)
- query host metrics such as `system_cpu_time`, `system_memory_usage`, or `system_filesystem_usage`
- create dashboards or alerts once data is visible

## Common Metric Families

| Metric family | Examples |
| --- | --- |
| CPU | `system_cpu_time`, `system_cpu_utilization`, `system_cpu_load_average_1m` |
| Memory | `system_memory_usage`, `system_memory_utilization` |
| Disk | `system_disk_io`, `system_disk_operations`, `system_disk_io_time` |
| Filesystem | `system_filesystem_usage`, `system_filesystem_utilization`, `system_filesystem_inodes_usage` |
| Network | `system_network_io`, `system_network_packets`, `system_network_errors` |
| Paging | `system_paging_usage`, `system_paging_faults`, `system_paging_operations` |
| Process | `system_processes_count`, `process_cpu_time`, `process_memory_usage` |

For the complete upstream reference, see the [hostmetrics receiver documentation](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/hostmetricsreceiver).
