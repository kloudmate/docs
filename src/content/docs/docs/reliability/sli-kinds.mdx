Step 2 of the SLO wizard picks the **SLI** — the specific signal you measure compliance against. KloudMate ships seven SLI kinds, each with its own conditional form fields. This page walks through them with a "When to use this" callout, the form fields, and worked examples.

For the APM, log-based, and custom-metric kinds, the service-name, metric-name, severity, and attribute pickers suggest values discovered from your workspace's OTel telemetry (spans / logs / metrics stores). All pickers are free-solo, so you can type a value that doesn't have telemetry yet.

## Incident availability

**When to use:** *"This service should be up at least 99.9% of the time, measured by unresolved incident duration."*

Fields:

- **Severities (optional)** — multi-select, free-text (e.g. `critical`, `high`). Leave empty to count all severities.

Incident availability anchors on incident duration on the SLO's service. The SLI is *"share of the window when no incident at the picked severities was open."*

## APM latency

**When to use:** *"P99 of this service should be under 200 ms."* (RED's Duration.)

Fields:

- **Service name** — required. Picker suggests services emitting spans.
- **Latency threshold (ms)** — required.

The SLI counts spans whose duration is below the threshold as good, all spans as denominator. A 200 ms threshold with a 99% target means *"at least 99% of spans should be under 200 ms."*

## APM error rate

**When to use:** *"Less than 1% of requests to this service should error."* (RED's Errors.)

Fields:

- **Service name** — required. Picker suggests services emitting spans.
- **Error status values** — required, multi. Picker suggests values found for `http.status_code` in the workspace's spans.

The SLI is *"share of spans whose `http.status_code` is **not** in the error list."*

## APM request rate

**When to use:** *"This service should serve at least 60 RPM continuously."* (RED's Rate, time-sliced.)

Fields:

- **Service name** — required. Picker suggests services emitting spans.
- **Min requests / minute** — required.
- **Bucket size (minutes, optional)** — default `1`. Power users can tune the time-slicing granularity here; the default 1-minute bucket is fine for most cases.

The SLI counts each bucket as good if its request rate is at or above the minimum, bad otherwise.

## APM trace ratio

**When to use:** power-user — *"Build an SLI from any pair of span-attribute filters."* Examples: cache hit rate, payment-success rate, business-event ratios.

Fields:

- **Service name** — optional. When set, applies implicitly to both filter sets.
- **Numerator filters** — required. Spans matching **all** of these attribute filters count as good.
- **Denominator filters** — required. Spans matching **all** of these form the universe (good + bad).

Filter rows are key/op/value triplets — see [Filter rows](#filter-rows) below.

## Custom metric

**When to use:** *"Build an SLI from OTLP metrics."*

A tabbed switch above the form picks the mode:

### Ratio of counts (default)

Both numerator and denominator are SUM-aggregated metrics with optional filters. Used for counter-based SLIs like `http.requests.success` over `http.requests.total`.

Fields:

- **Numerator metric name** + optional filters.
- **Denominator metric name** + optional filters.

### Value threshold

Numerator counts observations whose value matches a comparison (`<`, `≤`, `>`, `≥`). Denominator is the total count of observations. Used for gauge-based SLIs like synthetic latency or SSL-cert-days-remaining.

Fields:

- **Metric name** + optional filters.
- **Comparison** — `<`, `≤`, `>`, `≥`.
- **Threshold value**.

Metric name pickers suggest metric names from the workspace's metrics store; filter rows suggest the metric's label keys and values.

## Log-based

**When to use:** *"Less than 1% of this service's logs should be errors."*

Fields:

- **Service name** — required. Picker suggests services emitting logs.
- **Error severities** — required, multi. Picker suggests values found for `severity_text` in the workspace's logs (e.g. `ERROR`, `FATAL`).
- **Body pattern** — optional regex against the log body.
- **Attribute filters** — optional key/op/value rows against log attributes — see [Filter rows](#filter-rows) below.

## Filter rows

The filter rows used by trace-ratio, custom-metric, and log-based SLIs have three columns:

- **Attribute** — autocomplete that suggests attribute keys discovered from the relevant OTel store (spans / logs / metrics).
- **Operator** — `Equals` / `Not equals` / `In (any of)` / `Not in`.
- **Value** — autocomplete that suggests values for the chosen attribute. Switches to multi-select for `In` / `Not in`, scalar for `Equals` / `Not equals`.

**+ Add filter** appends a new row; the trash icon removes one.
