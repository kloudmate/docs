Instrumenting your existing Java application with the OpenTelemetry SDK gives you the flexibility to capture custom metrics, manual spans, and tailored application context.

## Installation

Add the OpenTelemetry BOM (Bill of Materials) and dependencies to your `pom.xml` (Maven) or `build.gradle` (Gradle):

**Maven** (`pom.xml`):
```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.opentelemetry</groupId>
      <artifactId>opentelemetry-bom</artifactId>
      <version>1.34.1</version> <!-- Use the latest version -->
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
<dependencies>
  <dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-api</artifactId>
  </dependency>
  <dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-sdk</artifactId>
  </dependency>
  <dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-exporter-otlp</artifactId>
  </dependency>
</dependencies>
```

## Configuration

Configure the OpenTelemetry exporter to send data to the KloudMate Agent's OTLP endpoint. By default, the KloudMate agent listens on port `4318` for HTTP OTLP traffic.

You can configure the endpoint via environment variables before running your instrumented code:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="http://KM_AGENT_HOST:4318"
export OTEL_SERVICE_NAME="your-java-service"
```
*(Replace `KM_AGENT_HOST` with the IP address or hostname of your KloudMate Agent).*
