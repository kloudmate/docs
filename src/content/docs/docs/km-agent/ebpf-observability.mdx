KM Agent supports eBPF-powered observability for Linux environments. This is the preferred zero-code path when you want service-level APM visibility, network telemetry, and kernel-level database activity signals without modifying applications.

Unlike SDK-based instrumentation, eBPF is part of the KM Agent configuration. It should be documented and configured with the agent, not under the `Traces` product area.

## What eBPF Gives You

When eBPF is enabled through KM Agent, KloudMate can collect:

- application RED metrics such as request rate, error rate, and latency
- trace spans for supported traffic flows
- service dependency information used by APM and Service Map
- L3 and L4 network flow telemetry
- database activity signals used by [Database Activity Monitoring](../database-monitoring/database-activity-monitoring-dam/)

## Where This Data Appears

After eBPF data is flowing, use:

- [APM](../traces/apm/) for service-level latency, throughput, and dependency views
- [Traces](../traces/) for request-level trace inspection
- [Database Activity Monitoring](../database-monitoring/database-activity-monitoring-dam/) for kernel-level database visibility

## Prerequisites

- a Linux host or Kubernetes node
- kernel `5.8+` recommended, with some features available on `4.18+`
- sufficient privileges for the KM Agent eBPF receiver
- KM Agent installed on the host or cluster

Use these setup guides first:

- [Linux Agent](./installation/linux-agent/)
- [Kubernetes Agent](./installation/kubernetes-agent/)
- [Configuration](./configuration/)

## Recommended Rollout

1. Install KM Agent on Linux or Kubernetes.
2. Enable APM or eBPF-related features in the agent configuration.
3. Start with broad zero-code coverage.
4. Add [Manual Instrumentation](../traces/manual-instrumentation/) only where you need custom business logic spans or richer application context.

## Base eBPF Configuration

The eBPF receiver is configured through the KM Agent `config.yaml`.

```yaml
metrics:
  features:
    - application
    - application_span
    - network

discovery:
  services:
    - name: all-services
      namespace: default
      open_ports: "80, 443, 8080, 8443, 5432, 3306, 6379, 9092, 27017"

network:
  enable: true
  source: tc
  direction: both

attributes:
  kubernetes:
    enable: true
```

This enables:

- service-level RED metrics
- span generation for supported traffic
- network telemetry
- Kubernetes enrichment when applicable

## Advanced eBPF Options

Use the `ebpf` block for database heuristics and cache tuning:

```yaml
ebpf:
  heuristic_sql_detect: true
  mysql_prepared_statements_cache_size: 1024
  postgres_prepared_statements_cache_size: 1024
```

This is especially relevant for high-load database environments and for [Database Activity Monitoring](../database-monitoring/database-activity-monitoring-dam/).

## Kubernetes Notes

When using the [Kubernetes Agent](./installation/kubernetes-agent/), the KM Agent handles the DaemonSet-level installation and the necessary runtime integration. You do not need a separate APM product setup page for each runtime when you are using the KM Agent path.

If you are enabling APM on Kubernetes workloads, start with [APM Setup Instructions](./installation/kubernetes-agent/#apm-setup-instructions).
