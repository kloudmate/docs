The `Traces` section in KloudMate gives you end-to-end visibility into how requests travel across your services. It is the request-centric workspace for investigating individual traces, spans, and trace attributes.

Use it to:

- inspect full request journeys across services
- search spans by service, status, method, severity, and other attributes
- review span timing, events, and metadata
- compare traces, root spans, and service-level trace activity
- correlate trace findings with logs and APM views

## Traces vs. APM

Traces and APM are related, but they solve different problems:

- **Traces** is request-centric. Use it to debug a specific request, span, or execution path.
- **APM** is service-centric. Use it to compare latency, throughput, error rate, and dependencies across services.
- **Metrics** is where broader application, infrastructure, database, and custom metric documentation lives.

Start here when you need to inspect trace-level detail. Start in [APM](./apm/) when you need higher-level service health and dependency analysis.

## Instrumentation Paths

KloudMate supports multiple ways to generate tracing data:

- [KM Agent eBPF Observability](../km-agent/ebpf-observability/) for kernel-level tracing and RED metrics without code changes or restarts
- [Kubernetes APM with KM Agent](./auto-zero-code-instrumentation/) for the preferred Kubernetes APM flow through the KM Agent
- [Manual Instrumentation](./manual-instrumentation/) for SDK-based tracing with the most control

## Traces Section Walkthrough

Click **Traces** in the left navigation menu to open the section.

At the top of the page, the **span volume graph** visualizes trace activity over the selected time range. This gives you a quick pulse check on traffic patterns before you inspect individual traces.

## Searching and Filtering

### Search Bar

Search across traces using span attributes. Click the search bar to see the list of available attributes.

![image](./images/traces-2.jpeg)

Click the filter icon on the right to open the full attribute picker. Active filters appear as tags in the search bar and can be removed individually.

![image](./images/traces-3.jpeg)

### Sidebar Filters

Use the left sidebar to filter results by:

- Service
- HTTP Method
- HTTP Status
- Severity
- Database Name

Each filter section includes a search box for quick lookup. When filters are active, a recent-filters notice appears at the top of the sidebar.

![image](./images/traces-4.jpeg)

## Saved Queries

Click **Saved Queries** to view and apply previously saved searches. To save a new query, click the dropdown arrow next to **Saved Queries** and select **Add New**.

![image](./images/traces-5.jpeg)

## Traces Result Views

### Spans

The **Spans** tab is the default view. It lists every individual span captured within the selected time range and active filters. Each row displays `Timestamp`, `Span Name`, `Services`, `Duration`, and `Error`.

This view is best when you need the most granular view of tracing activity.

![image](./images/traces-6.jpeg)

### Trace Summary

The **Trace Summary** tab groups spans into complete traces, giving you a higher-level view of end-to-end request journeys. Each row represents a single trace, showing its entry point, number of services, spans involved, total duration, and any errors.

![image](./images/traces-2.png)

### Root Spans

The **Root Spans** tab shows only the root span from each trace. This makes it easier to compare top-level requests without the noise of child spans.

![image](./images/traces-3.png)

### Services

The **Services** tab summarizes traffic by service so you can identify hotspots, dependency trends, and the applications generating the most trace volume.

![image](./images/traces-4.png)
